# Public data change

`src/data/` is the published flagship bundle. It is public on purpose, and every file in it
is either **generated by a script** or a **hand-maintained declaration**. Editing a generated
file by hand desynchronizes it from its audit and fails CI.

## Generated vs. declared

| File | Produced by |
|---|---|
| `music_dna_compiled.json` | `npm run compile:data -- --source-dir <path>` |
| `music_dna_genre_catalog.json`, `artist_genre_assertions.v1.json` | `npm run genres:build` |
| `genre_ontology.v1.json` | `npm run genres:sync` |
| `artist_knowledge_manifest*.json` | `npm run knowledge:manifest` |
| `offline_artist_knowledge.json` | `npm run knowledge:artists` |
| `artist_enrichment_he.json` | `npm run i18n:hebrew` |
| `share_metrics.json` | `npm run share:sync` |
| `public_dataset_manifest.json` | **Declared by hand** — must match the bundle |
| `artist_external_identity_policy.json` | **Declared by hand** — reviewed identity decisions |

`music_dna_mock.json` is the test fixture; `src/test-setup.ts` swaps it in for the real
dataset globally, so tests never read flagship data.

## Procedure

1. **Never point the compiler at a personal directory implicitly.** The source path is
   always explicit: `npm run compile:data -- --source-dir <path> [--lastfm-file <csv>]`.
2. Regenerate every downstream artifact the change touches (genres → knowledge → Hebrew →
   share metrics), in that order.
3. **Read the live audit, not the prose:**
   ```bash
   npm run audit:data      # coverage + priority queue
   npm run audit:identity  # duplicate/variant groups, rejected external matches
   npm run audit:links     # curated media profiles and embeds
   ```
   Never copy a coverage number out of a Markdown file — those age. The queue you print
   now is the truth.
4. **Update `public_dataset_manifest.json`.** Exact-granularity sections — `sessions`,
   `obsessions`, `daily_plays`, `platform_breakdown`, `snapshot_freshness`, `recent_pulse`
   — need an explicit status of `published-curated`, `redacted` or `omitted`.
5. **Run the privacy audit**: `node scripts/audit_public_bundle_privacy.mjs`.
   It scans *every* tracked text file — `.md` included — for forbidden raw keys
   (`ip`, `email`, `user_id`, `device_id`, `latitude`, `user_agent`, …). If you need to
   document a flagged value, **describe it; never quote it**, or the doc itself trips the audit.
6. Close with `npm run verify`.

## Artist identity and media

Before proposing any artist portrait, embed or external link, read
`src/data/artist_external_identity_policy.json`. It records reviewed historical name
relationships, transliteration splits and provider matches that were **rejected on purpose**.
Reintroducing one is a regression, not a discovery.

When an identity is ambiguous, keep the honest unresolved state. The audit is reversible by
design: variant groups are documented, and **no row is silently merged or deleted**.

## The boundary

- Raw exports, API keys, account identifiers, private CVs and browser-storage dumps never
  enter Git — not even as a fixture.
- Visitor archives are parsed and stored in the browser only.
- A MusicBee XML is reduced to an allowlisted snapshot; local paths and persistent IDs are
  discarded.
- Any **new runtime network request** must be documented in `README.md` and
  `docs/architecture/PRIVACY_THREAT_MODEL.md` in the same change.
